Orion compiles to LLVM IR and then to a native binary. Indentation makes blocks. There is no null and there are no exceptions. Every code block below is a whole program, and every one of them is compiled by tools/docs_check.sh — if a sample here stops working, the build says so.

1. Hello

fn main() -> int:
    print_line("hello")
    0

Build and run it:

orbit run hello.or

A block's value is its last expression, so no return is needed — though return exists for leaving early. What main returns becomes the process exit code.

No project, no config, no output path to name. orbit build hello.or leaves a hello executable beside the source. For something larger, orbit new myapp scaffolds a project and the same run, build and test work inside it.

2. Names

fn main() -> int:
    x = 41            # bound once
    mut total = 0     # this one changes
    total = total + x
    total += 1
    ready = true      # bool: true / false, with and / or / not
    ratio = 1.5       # float
    if ready and not (ratio > 2.0) then total else 0

Plain = binds a new name. mut marks one you mean to reassign, and the compiler holds you to it. Types are inferred; write one when you want it checked, as in mut n: int = 0. The types you get for free are int, float, bool and Text. const LIMIT = 10 names a compile-time constant and type Meters = int names an existing type.

3. Text

fn main() -> int:
    name = "world"
    n = 3
    print_line("hello {name}, {n} times, {n * 2} in total")
    print_line("a literal brace: \{ and \}")
    0

Every string literal is an interpolation. A hole {...} takes any expression, not just a name. Escape a real brace as \{. Three or more parts compile to a single join, so building a line in a loop does not quietly cost you one allocation per piece.

4. Branching

fn classify(n: int) -> Text:
    match:
        n < 0:  "negative"
        n == 0: "zero"
        else:   "positive"

fn main() -> int:
    print_line(classify(0 - 5))
    label = if 1 == 1 then "yes" else "no"
    print_line(label)
    0

match: with no subject is a chain of conditions and the first true arm wins. It is what you use instead of else if. if c then a else b is the one-line form; the indented if c: / else: is the block form.

5. Loops

fn main() -> int:
    mut sum = 0
    loop i in 0..<5:                          # 0 1 2 3 4
        sum += i
    loop i in 1..=3:                          # 1 2 3
        sum += i
    doubled = loop x in [1, 2, 3]: x * 2      # [2, 4, 6]
    big = loop x in [1, 2, 3]:                # [2, 3]
        if x > 1: yield x
    loop:
        break
    sum + len(doubled) + len(big)

loop is the only iteration keyword. In statement position it loops; in expression position it collects each body value into a list, which is where map and filter come from. A one-liner yields its trailing expression; an indented body yields explicitly with yield, and filters with an if that only yields sometimes. 0..<5 excludes the end, 1..=3 includes it, and a bare loop: runs until break.

6. Lists and maps

fn main() -> int:
    xs = [10, 20, 30]
    ys = push(xs, 40)          # push returns a new list
    m = {"a": 1, "b": 2}
    print_line("first={xs[0]} len={len(ys)} b={get(m, "b")}")
    xs[0] + len(ys)

push copies. That keeps value semantics unconditional, and it means x = push(x, v) in a tight loop is quadratic — for a hot accumulator, push_mut is the audited way to append in place. Index with xs[0]; at, len, get and has are the function forms, all built in and needing no import.

7. Types

type Player: name: Text, hp: int

type Shape:
    Circle(int)
    Rect(int, int)

fn area(s: Shape) -> int:
    match s:
        Circle(r) -> 3 * r * r
        Rect(w, h) -> w * h

fn divmod(a: int, b: int) -> (int, int):
    (a / b, a % b)

fn main() -> int:
    p = Player{name: "Hero", hp: 100}
    q, r = divmod(17, 5)
    print_line("{p.name} has {p.hp} hp; 17/5 is {q} rem {r}")
    area(Shape.Rect(6, 7))

One keyword for both shapes. Fields on a line make a record, reached with p.name. Variants make a sum type, built as Shape.Rect(6, 7) and read by match, which is checked for exhaustiveness. _ is the catch-all pattern, and if let Circle(r) = s: handles the single-case check without a full match.

A tuple (a, b) is an anonymous struct, so its slots keep their own types and (int, Text) is a real pair. That is how a function returns more than one thing, and q, r = divmod(17, 5) takes them apart. Tuple patterns work in match too.

8. Functions, lambdas, orbs

use text
use iter

fn main() -> int:
    words = split("alpha,beta,gamma", ",")
    lengths = loop w in words: len(w)
    double = fn(x): x * 2
    print_line("words={len(words)} letters={sum(lengths)}")
    double(21)

A library is an orb: use text brings one in, and pub fn is what an orb exports. Each orb is its own namespace. A lambda is fn(params): body and closes over what it needs. Any function can also be called method-style, so trim(s) and s.trim() are the same call.

9. When it goes wrong

type Res<T>:
    Ok(T)
    Err(Text)

fn safe_div(a: int, b: int) -> Res<int>:
    if b == 0:
        Res.Err("divide by zero")
    else:
        Res.Ok(a / b)

fn calc(x: int) -> Res<int>:
    v = safe_div(84, x)?      # unwrap, or return the Err
    Res.Ok(v * 2)

fn main() -> int:
    require 1 == 1            # traps if false
    defer print_line("cleanup runs last")
    match calc(2):
        Ok(v) -> v
        Err(_) -> 0

There is no null to forget to check and no exception to forget to catch. Failure is a value: give it a variant, and ? either unwraps the good case or returns the bad one to your caller. Types take parameters, so one Res<T> covers every payload rather than one per type. require and ensure are runtime contracts that trap on a false condition. defer runs at block end, last registered first, and before any return.

10. Talking to the outside

fn main() -> int:
    who = if argc() > 1 then argv(1) else "world"
    print_line("hello {who}")
    file_write("greeting.txt", "hello {who}")
    back = file_read("greeting.txt")
    len(back)

argc and argv are the command line, print_line is stdout, and file_read and file_write move whole files at a time. All built in, no import. For more than that the os orb has run_command, mkdir_all, file_exists.

11. Two things worth knowing exist

Neither is needed on your first day. A guide that never mentions them hides the most interesting ideas in the language, so here they are, named rather than taught.

Effects let a function ask for something without knowing who answers. perform raises the request, handle answers it, and resume goes back to where it was asked.

effect Log:
    msg: fn(line: Text) -> Text

handle Log.msg(line: Text) -> Text:
    print_line("log: {line}")
    resume("ok")

fn work() -> int:
    perform Log.msg("starting")
    42

fn main() -> int:
    work()

Parallelism is real OS threads, and deterministic: each worker writes only its own slot and the reduction is order-independent, so the answer does not depend on timing.

fn double(x: int) -> int:
    x * 2

fn main() -> int:
    workers = [double, double, double]
    par_run(workers, 7)     # 3 threads, 3 x 14 == 42

The effects above are one-shot: the handler resumes exactly once and synchronously. That is the supported core and it works on every platform. Handlers that outlive their own resume (ask and resume_with) are experimental — that is the same machinery async needs, and it runs on Windows fibers. Elsewhere resumable_ok() reports 0 and ask refuses rather than pretending. Those, plus tasks with spawn and await, live in examples/tests/tests/ as test_42_effects, test_42_parallel and test_42_delimited_resume.
