Orion compiles to LLVM IR and then to a native binary. Indentation makes blocks. There is no null and there are no exceptions. Every code block below is a WHOLE program, and every one is compiled by tools/docs_check.sh - if a sample here stops working, the build says so. The syntax reference, in Swedish, is syntaxreferensen.

1. Hello

define main():
    print_line("hello")

Build and run it:

orbit run hello.or

A block's value is its last expression, so no return is needed - though return exists for leaving early. main returns nothing: failure travels as values and effects, not exit codes.

No project, no config, no output path to name. orbit build hello.or leaves a hello executable beside the source. For something larger, orbit new myapp scaffolds a project and the same run, build and test work inside it.

2. Names

define main():
    x = 41              # bound once
    edit total = 0      # this one may change
    total = total + x
    total += 1
    ready = true        # truth: true / false, with and / or / not
    ratio = 1.5         # number
    if ready and not (ratio > 2.0):
        print_line("{total}")

Plain = binds a name, and everything is immutable by default. edit marks the one binding you mean to change, and the compiler holds you to it. Types are inferred; write one when you want it checked, as in edit n: number = 0. The types you get for free are number, truth, text and table. A top-level binding like max_players = 8 is a constant - immutability needs no extra keyword - and type meters = number names an existing type.

Equality is a word: x is 5, name is not "". Order can be symbols or words, whichever reads better where you are: hp < 10 and hp is less than 10 are the same test, as are <= / is at most and >= / is at least.

3. Text

define main():
    name = "world"
    n = 3
    print_line("hello {name}, {n} times, {n * 2} in total")
    print_line("a literal brace: \{ and \}")

Every string literal is an interpolation. A hole {...} takes any expression, not just a name. Escape a real brace as \{. Three or more parts compile to a single join, so building a line in a loop does not quietly cost you one allocation per piece.

4. Branching

define classify(n: number) -> text:
    choose:
        n < 0  then "negative"
        n is 0 then "zero"
        else "positive"

define main():
    print_line(classify(0 - 5))
    label = if 1 is 1 then "yes" else "no"
    print_line(label)

choose: with no subject is a chain of conditions: the first true arm wins, and it is what you use instead of else if. An arm reads condition then result, and else catches the rest - else never takes a then, same as in the one-line if c then a else b. Everything is an expression: the block form if c: / else: produces a value too.

5. Say what, not how

use iter

define main():
    numbers = [4, 1, 9, 2]
    total   = sum(numbers)                     # 16
    doubled = each(numbers, (n): n * 2)        # [8, 2, 18, 4]
    big     = keep(numbers, (n): n > 3)        # [4, 9]
    print_line("{total} {length(doubled)} {length(big)}")

Most code over a collection states the intent - sum, each, keep, combine - and the compiler owns the mechanism: chains fuse with no intermediate lists, layout and vectorization are its job, not yours. When you do need to walk things yourself, there is exactly one iteration keyword:

define main():
    edit total = 0
    loop i in 1 to 3:                                 # 1 2 3
        total += i
    doubled = loop x in [1, 2, 3]: collect x * 2      # [2, 4, 6]
    big = loop x in [1, 2, 3] where x > 1: collect x  # [2, 3]
    print_line("{total + length(doubled) + length(big)}")

collect gathers values into a list - each and keep are built from it - and where filters the run. The ranges read the way English does: 0 until 5 stops before 5, 1 to 3 includes 3. A bare loop: runs until break.

6. Lists and tables

define main():
    xs = [10, 20, 30]
    ys = append(xs, 40)          # append returns a new list
    m = {"a": 1, "b": 2}
    print_line("first={xs[0]} len={length(ys)} b={get(m, "b")}")

Value semantics are unconditional: nothing is secretly shared. The compiler proves when a list has a single owner and mutates it in place, so xs = append(xs, v) in a hot loop costs what a mutation costs. Index with xs[0]; len, get, set and has are built in and need no import. A table holds key–value pairs with text keys, and get() is typed.

7. Types

type player: name: text, hp: number

type shape:
    circle(number)
    rect(number, number)

define area(s: shape) -> number:
    choose s:
        circle(r)  then 3 * r * r
        rect(w, h) then w * h

define divmod(a: number, b: number) -> (number, number):
    (a // b, a % b)

define main():
    p = player{name: "Hero", hp: 100}
    q, r = divmod(17, 5)
    print_line("{p.name} has {p.hp} hp; 17 // 5 is {q} rem {r}")
    print_line("{area(shape.rect(6, 7))}")

One keyword for both shapes, and everything is lowercase. Fields on a line make a record, reached with p.name. Variants make a sum type, built as shape.rect(6, 7) and read by choose, which is checked for exhaustiveness; _ is the catch-all pattern, and if let circle(r) = s: handles a single case without a full choose. / is real division and // is floor division - the answer never depends on inferred types.

A tuple (a, b) is an anonymous struct, so its slots keep their own types and (number, text) is a real pair. That is how a function returns more than one thing, and q, r = divmod(17, 5) takes them apart. Tuple patterns work in choose too.

8. Functions, lambdas, orbs

use iter
use text

define greet(name: text, loud = false):
    if loud:
        print_line(upper("hi {name}"))
    else:
        print_line("hi {name}")

define main():
    greet("Ada")
    greet(name: "Bo", loud: true)
    words = split("alpha,beta,gamma", ",")
    lengths = loop w in words: collect length(w)
    total = combine(lengths, 0, (a, b): a + b)
    print_line("words={length(words)} letters={total}")

A library is an orb: use text brings one in, and public define is what an orb exports. Return types are inferred for private functions; a public one may state its contract with -> type. At the call site, arguments can carry their names - greet(name: "Bo", loud: true) reads without opening the definition - and a parameter can hold a default. An anonymous function is just (params): body. Any function can also be called method-style, so trim(s) and s.trim() are the same call. A generic function introduces its type variable as a word: define first given item (items: list of item) -> maybe item.

9. When it goes wrong

type outcome:
    ok(number)
    error(text)

define safe_div(a: number, b: number) -> outcome:
    if b is 0:
        outcome.error("divide by zero")
    else:
        outcome.ok(a // b)

define calc(x: number) -> outcome:
    v = try safe_div(84, x)      # unwrap ok, or pass the error up
    outcome.ok(v * 2)

define main():
    require 1 is 1               # traps if false
    defer print_line("cleanup runs last")
    choose calc(2):
        ok(v)    then print_line("{v}")
        error(_) then print_line("failed")

There is no null to forget to check, no exception to forget to catch, no try/catch. Failure is a value: give it a sum type with an ok and an error variant, and try either unwraps the good case or returns the bad one to your caller. The result and option orbs ship that shape ready-made. require and ensure are runtime contracts that trap on a false condition. defer runs at block end, last registered first, and before any return.

10. Talking to the outside

use os

define main():
    args = arguments()
    who = if length(args) > 1 then at(args, 1) else "world"
    print_line("hello {who}")
    file_write("greeting.txt", "hello {who}")
    back = file_read("greeting.txt")
    print_line("{length(back)} bytes round-tripped")

arguments() is the command line as a list of text, print_line is stdout, and file_read / file_write move whole files at a time. All built in, no import. IO, time and randomness are becoming effects: a public function that touches the outside world says so in its signature - public define save(w: world) uses files: - so reading the signature tells you what a function can do, and a test swaps the handler instead of mocking. Private functions and main are inferred.

11. Two things worth knowing exist

Neither is needed on your first day. A guide that never mentions them hides the most interesting ideas in the language, so here they are, named rather than taught.

Effects let a function ask for something without knowing who answers. perform raises the request, handle answers it, and resume goes back to where it was asked.

effect log:
    msg: (line: text) -> text

handle log.msg(line: text) -> text:
    print_line("log: {line}")
    resume("ok")

define work() -> number:
    perform log.msg("starting")
    42

define main():
    print_line("{work()}")

Parallelism is real OS threads, and deterministic: each worker writes only its own slot and the reduction is order-independent, so the answer does not depend on timing.

define double(x: number) -> number:
    x * 2

define main():
    workers = [double, double, double]
    print_line("{par_run(workers, 7)}")     # 3 threads, 3 x 14 is 42

The effects above are one-shot: the handler resumes exactly once and synchronously. That is the supported core and it works on every platform. Handlers that outlive their own resume (ask and resume_with) are experimental - that is the same machinery async needs, and it runs on Windows fibers. Elsewhere resumable_ok() reports 0 and ask refuses rather than pretending.
